Task 1: Drawing Single-Color Triangles

Rasterizing is the process of rendering vector graphics into 2D pixel images. To rasterize a triangle, we simply sample it in 2D, wherein we evaluate each pixel to determine if it falls inside the triangle. If the pixel does, it is colored in. In terms of code implementation, we can perform three line tests for each pixel, where we construct the lines formed by each pair of the triangle's vertices. To evaluate a pixel's center relative to a line, we use the equation
\( L_i(x, y) = -(x - X_i)*(Y_{i+1} - Y_i) + (y - Y_i)* (X_{i+1} - X_i) \),
where \( (X_i, Y_i) \) is one vertex of the triangle and \( (X_{i+1}, Y_{i+1}) \) is the subsequent one. If \( L(x, y) = 0 \), the point is on the line (and therefore the boundary of the triangle); if \( L(x, y) > 0 \), it's above the line, and otherwise it's below the line. Since we consider points on a triangle's boundary to be within the triangle, a point is therefore inside the triangle if \( L(x, y) >= 0 \) for all 3 line segments. (I also discovered via brute force that a point is in the triangle if \( L(x, y) < 0 \) for all 3 line segments -- it's not possible for points outside of the triangle to have all three \( L(x, y) \) values be the same sign!)

I used the simple bounding box algorithm to minimize the number of samples I needed to evaluate, so it is (hopefully) equivalent and no worse. I identified the minimum x- and y-coordinates containing the full triangle and used that for my bounding box, where I only sampled the pixel centers within those coordinates and none outside of them.

Task 2: Antialiasing by Supersampling

Aliasing occurs when high-frequency signals aren't sampled at sufficiently high rates and thus appear as lower frequencies. When rasterizing images, aliasing can appear as jagged edges along what should be a smooth line. Supersampling is a very useful technique for antialiasing, which smoothes out the appearance of these jagged edges. The overall process of supersampling involves artificially increasing our sampling rate for an image, and then downsampling each subset of supersamples into a value for each pixel. This has the effect of removing high-frequency signals prior to sampling an image, thus diminishing the appearance of "jaggies."

In my code, I expanded the sample buffer's width and height each by a factor equal to \( sqrt(sample\_rate) \), so that each pixel contains \( sample\_rate \) supersamples. Each supersample is sampled using the same method of point-in-triangle tests to see if it should be colored in; if so, that color is stored in the sample buffer array element corresponding to that supersample. Afterwards, the sample buffer is downsampled, meaning that for each pixel, all of its supersamples' color values are then averaged, and that average color is used to fill in the frame buffer for that pixel.

The result of this antialiasing via supersampling is that pixels near the boundaries of certain shapes will also be filled in with colors that are a mix of adjacent pixels, which visually smooths out the jagged edges when viewed from further away. See the examples below; at higher sampling rates, the rightmost tip of the red triangle isn't detached but instead filled in with color averages of surrounding pixels, so that the triangle appears to be fully continous. The 16x sample rate image overall appears much smoother compared to the 1x sample rate image.

Task 4: Barycentric Coordinates

Barycentric coordinates are (as the name suggests) a coordinate system for triangles. Given three vertices of a triangle A, B, and C in Cartesian coordinates, we can express a point (x, y) within the triangle as a weighted combination of these vertices, such that
\( (x, y) = \alpha * A + \beta * B + \gamma * C \),
\( \alpha + \beta + \gamma = 1 \),
and \( \alpha >= 0, \, \beta >= 0, \, and \; \gamma >= 0 \).
The barycentric coordinates of \( (x, y) \) are therefore \( (\alpha, \beta, \gamma) \). See the diagram below. This coordinate system linearly interpolates values located at the triangle's vertices, which is very useful for coloring triangles with interpolation -- if vertex A is red, vertex B is green, and vertex C is blue, the color at point (x, y) will be a weighted combination of the values of these colors: \( color(x, y) = \alpha * red + \beta * green + \gamma * blue \). This produces a color gradient effect when used in conjunction with rasterizing triangles; as the bounding box of the triangle is sampled, each pixel is filled in if it lies inside the triangle, and the pixel's color depends on its barycentric coordinates within the triangle.

Task 5: "Pixel Sampling" for Texture Mapping

Texture mapping can be performed by pixel sampling, which is just the same simple process we've been using to rasterize triangles: for each pixel in a triangle's bounding box, if it falls inside the triangle, it is rasterized and then assigned the color value of the corresponding texel, thus applying the texture to the triangle. In this code implementation, our goal is to map the coordinates (x, y) in the screen space to the coordinates (u, v) in the texture space. Since we have the coordinates of the triangle's vertices in screen space as well as their corresponding locations in texture space, barycentric coordinates make it very easy to find the texture space coordinates of any point located inside the triangle. I used the same formulas as in task 4 to calculate the screen sample's barycentric coordinates based on the triangle's vertices, and then implemented the two methods below for determining the texel color to use for the screen sample.

The nearest neighbors method is very simple and thus efficient: after scaling the barycentric coordinates of the screen sample based on the texture's height and width, we can find the nearest texel, which is just the texel that the sampling point is located in. The color of that texel is then used to fill the screen sample pixel. This approach can produce aliasing effects, especially when used to map high-resolution textures. However, the standard antialiasing approach via supersampling can be highly costly, because the sampling rate must also be extremely high to preserve the fine details of the texture.

Bilinear interpolation addresses this by performing antialiasing with just a few texels per pixel. Once again, we use the barycentric coordinates of the pixel sample location to find the corresponding texel, but we then consider the 4 closest texels rather than the singular texel. Using a series of bilinear interpolations between the pixel sampling location and these texel locations (2 horizontal, then 1 vertical in my implementation), we calculate the color for the pixel sample as a weighted average of the color of these surrounding texels. This method reduces the appearance of jaggies and smooths them over well, although it may muddle textures with fine/intricate details or high-contrast colors.
In the renderings of the UC Berkeley seal above, pixel sampling via bilinear interpolation provides greater visual clarity than nearest neighbors does. This is especially visible at 1x sampling rate, where in the rendering using nearest neighbors, "BER" could be mistaken for "AEP." (At least, that's what I saw initially, even though I knew it was the Berkeley seal. 😅) Bilinear interpolation both improves the readability of the letters and smooths out the curve of the blue banner, providing some slight antialiasing.

These examples demonstrate a visual difference between the two methods, where nearest neighbors pixel sampling will produce plenty of aliasing effects at low sampling rates, and bilinear interpolation is able to provide an anti-aliasing effect for textures. However, the advantage of nearest neighbors is that it's much more computationally efficient compared to bilinear interpolation, since bilinear interpolation must average the 4 texels closest to each sampling location. Consequently, using bilinear interpolation to render large scenes may take much more time than nearest neighbors pixel sampling would.

Task 6: "Level Sampling" with Mipmaps for Texture Mapping

One of the difficulties of texture mapping occurs when we "minify" or zoom out of images. In this case, each pixel is relatively larger and encompasses a large swath of texels, which makes it difficult to determine which texel's color should be used for that pixel; minor differences in texel selection can largely affect the appearance and potentially the quality of the resulting image. While bilinear interpolation can help mitigate aliasing effects, the number of texels corresponding to a pixel can grow exponentially in minification, making bilinear interpolation a very costly process.

The solution to this lies in mipmapping, which is when we sample lower-resolution textures for "faraway" details to avoid aliasing effects. Mipmaps are pre-computed versions of the texture at successively lower resolutions, where level 0 is the texture at its full size (e.g. 128x128), level 1 is the texture at half of level 0's resolution (64x64), and so on until we reach a 1x1 texture for the highest level. Pixels that cover a large jump in texture space should sample from a blurred texture at a higher level, and pixels that cover a small amount of texture space should sample from high-resolution textures at a lower level to maintain high detail. Once the proper mipmap level is identified, we can pixel sample from that level and use it for the pixel's color.

There are three methods of level sampling for texture mapping implemented in my code. The first is trivial -- at level 0, we're simply performing pixel sampling using either nearest neighbors or bilinear interpolation on the full-resolution texture, as in task 5. For the other methods, however, we need to identify the proper level to sample from. This is achieved by calculating the barycentric coordinates for the points (x, y), (x+1, y), and (x, y+1), which are uv, dx_uv, and dy_uv respectively. Then, we calculate additional vectors: duv_dx = dx_uv - uv and duv_dy = dy_uv - uv. These vectors are then scaled by the texture width and height, and we take their magnitudes to determine how much of the texture the pixel sample covers. Finally, we calculate the level using the maximum of these magnitudes; the target mipmap level is calculated as \( D = log\_2{(max\_magnitude)} \). In nearest level sampling, we simply round this level value to the closest integer and pixel sample from the texture corresponding to that mipmap level. In linear level sampling, we take the two mipmap levels adjacent to the calculated level, obtain the texel colors by pixel sampling each texture level, and then linearly interpolate those two colors to get the final resulting color for the pixel. When we use both linear level sampling and bilinear interpolation for pixel sampling, this is known as trilinear filtering, since we're using a linear interpolation of linear interpolations.

I used a high resolution screenshot (3840 x 2160) of one of my favorite video games, Mirror's Edge, to create the test_flight.svg, and focused on the lower-right section of the image since significant moiré effects are visible on the tiled floor without antialiasing. The screenshots below are all shown at 1x sample rate to display the differences from each combination of texture mapping methods.
At level 0, nearest neighbors produces the most visible amount of moiré effects, with 4 sets of concentric "circles" visible in the full image. The section focused by the pixel inspector shows that the lines of the tiles are very muddled, resulting in a dark blob, and the small scraps of paper on the floor look more like missing pixels than objects on the floor. Bilinear interpolation generally improves the whole image, increasing the continuity of the tile lines, reducing the muddled tile area, and adding a little dimensionality to the paper scraps.
Sampling from the nearest mipmap level provides the greatest visual improvement out of all of these combinations by adding some antialiasing. With nearest neighbors pixel sampling, the moiré effects have completely disappeared, and the tile lines are visibly continuous. However, the vertical tile lines are somewhat crooked, and the paper scraps have lost a lot of definition. Pixel sampling with bilinear interpolation once again improves the image overall, with the lines being much more straight and fine, and the paper scraps having their shape restored and even more dimensionality, although the image appears to be blurrier than the one rendered with nearest neighbors.
Interestingly, using linear level sampling doesn't improve on the images generated by nearest level sampling. This is likely just due to this specific zoom level on a very high resolution image, where the adjacent mipmap levels provide very similar or even the same color values for the texels at the pixel sampling locations.

With regards to the tradeoffs between speed, memory usage, and antialiasing power:
  • The fastest texture mapping method is to sample at mipmap level 0 using the nearest neighbors pixel sampling method, since it requires no additional computation beyond finding the barycentric coordinates of the current screen sample location within the bounding box. However, as shown in the example screenshots above, it provides no antialiasing and can manifest several artifacts such as moiré effects and jaggies. Bilinear interpolation at level 0 provides very slight antialiasing effects, but requires additional computation and therefore time in getting the averaged color values of the four nearest texels.
  • As shown above, nearest level sampling produces the greatest increase in antialiasing power and image quality, but it does require more computation and time from finding the vectors representing the change in texture space and then calculating the proper mipmap level to sample from based on those vectors. Adding bilinear interpolation of the texels to this of course increases the computation time, but produces the best antialiasing effects, even at 1x sampling rate.
  • The most costly combination of these level and pixel sampling methods is trilinear filtering, since it uses the results of bilinear interpolation pixel sampling on two different mipmap levels, then linearly interpolates between those results. It also may not improve the image further than nearest level bilinear interpolation does, depending on the zoom level.
  • Regardless of the specific texture mapping method, supersampling overall has the highest cost in terms of time, computation, AND memory usage because it requires that the total number of texture mapping operations be increased by \(sample\_rate * x \) per screen pixel, and then also necessitates a downsampling process for all of these stored supersample values. The end result is that supersampling with high sampling rates does a great job of antialiasing rasterized images. However, I would argue that nearest level bilinear interpolation is more effective for antialiasing than using level 0 nearest neighbor 16x sampling rate, since I observed more exaggerated jaggies with the latter. Supersampling therefore may not be worth the tradeoff in image quality and cost, especially in memory usage since no other texture mapping methods require nearly as much additional memory storage as expanding the sample buffer does.
