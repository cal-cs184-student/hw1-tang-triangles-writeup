Task 1: Drawing Single-Color Triangles

Rasterizing a triangle is simply sampling it in 2D, wherein we evaluate each pixel to determine if it falls inside the triangle. If the pixel does, it is colored in. In terms of code implementation, we can perform three line tests for each pixel, where we construct the lines formed by each pair of the triangle's vertices. To evaluate a pixel's center relative to a line, we use the equation
\( L_i(x, y) = -(x - X_i)*(Y_{i+1} - Y_i) + (y - Y_i)* (X_{i+1} - X_i) \),
where \( (X_i, Y_i) \) is one vertex of the triangle and \( (X_{i+1}, Y_{i+1}) \) is the subsequent one. If \( L(x, y) = 0 \), the point is on the line (and therefore the boundary of the triangle); if \( L(x, y) > 0 \), it's above the line, and otherwise it's below the line. A point is therefore inside the triangle if \( L(x, y) > 0 \) for all 3 line segments. (I also discovered via brute force that a point is in the triangle if \( L(x, y) < 0 \) for all 3 line segments -- it's not possible for points outside of the triangle to have all three \( L(x, y) \) values be the same sign!)

I used the simple bounding box algorithm to minimize the number of samples I needed to evaluate, so it is (hopefully) equivalent and no worse. I identified the minimum x- and y-coordinates containing the full triangle and used that for my bounding box, where I only sampled the pixel centers within those coordinates and none outside of them.

Task 2: Antialiasing by Supersampling

Aliasing occurs when high-frequency signals aren't sampled at sufficiently high rates and thus appear as lower frequencies. When rasterizing images, aliasing can appear as jagged edges along what should be a smooth line. Supersampling is a very useful technique for antialiasing, which smoothes out the appearance of these jagged edges. The overall process of supersampling involves artificially increasing our sampling rate for an image, and then downsampling each subset of supersamples into a value for each pixel. This has the effect of removing high-frequency signals prior to sampling an image, thus diminishing the appearance of "jaggies."

In my code, I expanded the sample buffer's width and height each by a factor equal to \( sqrt(sample\_rate) \), so that each pixel contains \( sample\_rate \) supersamples. Each supersample is sampled using the same method of point-in-triangle tests to see if it should be colored in; if so, that color is stored in the sample buffer array element corresponding to that supersample. Afterwards, the sample buffer is downsampled, meaning that for each pixel, all of its supersamples' color values are then averaged, and that average color is used to fill in the frame buffer for that pixel.

The result of this antialiasing via supersampling is that pixels near the boundaries of certain shapes will also be filled in with colors that are a mix of adjacent pixels, which visually smooths out the jagged edges when viewed from further away. See the examples below; at higher sampling rates, the rightmost tip of the red triangle isn't detached but instead filled in with color averages of surrounding pixels, with the 16x sample rate image appearing much smoother compared to the 1x sample rate image.

Task 3: Transforms

For task 3, I added transformations to the template given by transforms/robot.svg to get him to do a handstand! I first rotated the entire body 150 degrees to get it to be somewhat upside down. Next, I rotated the robot's left arm (the support for the handstand) -60 degrees to get it to be vertical and rotated its right arm 40 degrees. To give the robot's legs the appearance of being bent while in the air, I rotated both entire legs -30 degrees, then the lower legs 75 degrees. I also did some small translations to certain body parts throughout this process to keep them more visually aligned.
